# Domain Docs

## Layout

Use a single context:
- CONTEXT.md at the repository root for domain vocabulary.
- docs/adr/ for architectural decisions.

## Before exploring

Follow the current plan referenced by AGENTS.md.
Read CONTEXT.md and ADRs relevant to the area being explored.

If domain documents do not exist, proceed silently. Do not create
placeholders or suggest creating them upfront. The domain-modeling
skill creates them when terms or decisions are resolved.

## Vocabulary and decisions

Use the terms defined in CONTEXT.md.
If a term is missing, check existing project terminology before
recording a gap for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
including the decision and the reason for reconsidering it.
