# Data Model: Cadastros Auxiliares, Fornecedores e Navegação Contextual

## Persistent model

### Fornecedor

Parceiro comercial que pode ser relacionado a Compras e Produtos.

| Field | Type | Required | Validation | Notes |
| --- | --- | --- | --- | --- |
| `Id` | UUID | Yes | Generated by the existing base entity | Remains internal to routes, payloads, cache keys and relationships |
| `Nome` | Text | Yes | Non-empty after trim; maximum 150 characters under the existing mapping | Existing behavior is preserved |
| `Telefone` | Text | No | Blank/whitespace becomes null; trim before length validation; maximum 50 characters | No mask, country dependency or uniqueness rule |
| Existing audit fields | Existing types | Yes | Existing base entity rules | Update continues to refresh modification metadata |

### Persistence change

- Add nullable `Telefone`/`telefone` column with maximum length 50 to `fornecedores` through the existing naming convention.
- Do not define a default, unique index or data backfill.
- Existing rows remain valid with null phone.
- Migration down removes only the new column; no unrelated data is changed.

### Domain invariants

1. `Nome` remains mandatory and trimmed.
2. `Telefone` may be absent.
3. Null, empty and whitespace-only phone values represent the same absent state.
4. A non-null phone is trimmed and contains at most 50 characters.
5. Repeated phones are accepted.
6. An invalid update must not partially mutate the existing Fornecedor.

### State transitions

```text
Create(nome, phone?)
  -> validate and normalize
  -> Active Fornecedor with phone or null

Update(nome, phone?)
  -> validate all inputs
  -> replace name and phone atomically
  -> update modification metadata

Invalid create/update
  -> reject
  -> no persisted state change
```

## Transient UI models

### Supplier quick-create draft

| Field | Type | Initial state | Rule |
| --- | --- | --- | --- |
| `nome` | String | Empty | Required after trim |
| `telefone` | String | Empty | Optional; trim; maximum 50 characters |
| `errors` | Field map | Empty | Client feedback mirrors server contract; API message remains authoritative |
| `submitError` | Optional string | Null | Displays the actual API error within the modal |
| `isSubmitting` | Boolean | False | Prevents duplicate confirmation and disables closing actions that would create ambiguous state |

On success, the modal emits the complete created `Supplier`, resets its own draft and closes. It does not own or reset the Purchase/Product draft.

### Category quick-create draft

| `errors` | Field map | Empty | Same field-level contract as official creation |
| `submitError` | Optional string | Null | Actual API error displayed inside the modal |

On success, the modal emits the created `Category`, resets and closes without touching the Product draft.

### Compra em rascunho

Existing fields and item structure remain unchanged. The only new transition is:

```text
Draft with any populated fields/items
  -> open Supplier quick-create modal
  -> cancel/error: Draft unchanged
  -> creation success: fornecedorId = created Supplier.Id; every other field/item unchanged
```

If Products are empty, Purchase remains blocked. If only Suppliers are empty, the form remains available to open quick creation.

### Produto em rascunho

Existing fields remain unchanged. New transitions:

```text
Draft -> create Category -> categoriaId = created Category.Id; other fields unchanged
Draft -> create Supplier -> fornecedorId = created Supplier.Id; other fields unchanged
Cancel/error in either modal -> Draft unchanged
```

Product confirmation remains invalid without a Category. Supplier remains optional.

### Contextual navigation origin

Transient value transported only between controlled frontend routes.

| Field | Type | Required | Validation |
| --- | --- | --- | --- |
| `returnTo` | String path | No | Starts with exactly one `/`; has no origin, protocol or protocol-relative prefix; belongs to an allowed operational prefix |
| `fallbackHref` | String path | Yes | Static internal parent route supplied by each destination page |
| `transitionMarker` | Session value | No | One-time record with normalized destination, origin, timestamp and contract version; must match the current URL and `returnTo` and be at most 10 seconds old |

Resolution order:

1. `ContextualLink` records a marker only for an unmodified primary client-navigation click.
2. On destination mount, consume the marker before resolving the return action.
3. If marker, current destination and valid `returnTo` match within the short validity window, keep the origin in component state for the current mount.
4. Otherwise use the required `fallbackHref`.
5. Never delegate the decision to uncontrolled browser history or the document-wide navigation type.

`returnTo` is removed from the origin before a new contextual link is built, preventing nested chains and loops.

Allowed operational paths are `/` and paths whose pathname is equal to or below `/clientes`, `/fornecedores`, `/produtos`, `/compras`, `/vendas`, `/estoque`, `/financeiro` or `/configuracoes`. Authentication, API, framework assets and unknown prefixes are not valid origins.

## Relationships and non-changes

- Compra continues to reference Fornecedor by `FornecedorId`; no cardinality or stock behavior changes.
- Produto continues to reference Categoria and optional Fornecedor by identifiers; no cost or stock behavior changes.
- Removing GUIDs is presentation-only; all identifiers remain in contracts and internal relationships.
- No Venda, Estoque, Recebimento, Perda, Financeiro or analytics entity changes.
